Herogen 2

Pixel-art mobile RPG prototype built around character progression, territory development, equipment management, daily quests, and dungeon progression.

Ongoing project. This page tracks development progress and will be updated as more systems ship. Where a system was owned by another team member, it is noted in that section.

Role: Project Lead, Game Planner, Unity Game Programmer

Studio: Itchi Technology Limited

Platform: iOS & Android (mobile portrait)

Technologies: Unity, C#, Tilemaps, CSV data, Unity UI, Git

Project overview

Herogen 2 is a pixel-art mobile RPG prototype built around character progression, territory development, equipment management, daily quests, and dungeon progression.

As Project Lead and Unity Game Programmer, I planned the gameplay flow, coordinated feature integration, and implemented major game-ready systems and UI interactions. The visual UI design and character-creation system were provided by other team members.

Full game flow

1. Landing and main game entry

The player begins from the landing screen and enters the main game scene. The main scene acts as the central hub for accessing territory, character information, inventory, equipment, quests, shops, rankings, and dungeon content.

My contribution:

  • Main-scene integration
  • Game-ready UI panel setup
  • Popup prefab preparation
  • Panel navigation and interaction connections
  • Main HUD integration

2. Territory management

The main territory functions as the player's home area. Players can unlock new areas and place available objects or buildings onto the tilemap.

I implemented:

  • Territory unlock flow
  • Tilemap-based area handling
  • Placeable-object UI
  • Placement validation
  • Available-space checks
  • Inventory-capacity validation
  • Camera interaction
  • Unlock reveal and smoke effects

3. Character and equipment access

The player can open the character status and equipment panels from the main game. These panels display player information, equipment slots, stats, and item-related actions.

My contribution:

  • Character status panel integration
  • Equipment panel setup
  • Equipment slot UI
  • Player-stat display connections
  • Equipment stat comparison feedback
  • Equip and unequip interaction flow
  • Value increase/decrease animations

The character skin asset, character creation system, and character-edit functionality were handled by another team member using a purchased asset-store package.

4. Inventory and storage

The inventory allows players to inspect and manage their items throughout the game.

I implemented:

  • Inventory and bag panels
  • Item detail panels
  • Inventory filtering
  • Inventory sorting
  • Item stack handling
  • Capacity checks
  • Item selection
  • Storage/warehouse flow
  • Item movement between bag and storage
  • Item locking and favouriting
  • Selling and item actions
  • Reusable item and slot prefabs

This inventory system supports the equipment, enhancement, territory, shop, and dungeon reward flows.

5. Equipment enhancement

The enhancement panel allows players to improve equipment using resources and materials.

I implemented:

  • Enhancement panel
  • Equipment selection
  • Weapon enhancement flow
  • Enhancement cost display
  • Success-rate display
  • Enhancement validation
  • Result feedback
  • Inventory updates after enhancement
  • Enhancement slot layout
  • Upgrade stat feedback
  • Enhancement animations

6. Gems and equipment sockets

Equipment can support different socket configurations depending on the equipment or weapon type.

I implemented:

  • Gem-slot UI
  • Socket-slot UI
  • Socket-opening rules
  • Different socket configurations
  • Gem selection flow
  • Gem-related validation
  • Gem and socket layout adjustments
  • Item-state updates after socket actions

7. Daily quests

The daily quest system gives players additional objectives and rewards from the main game flow.

I implemented:

  • Quest data structure
  • CSV-based quest data
  • Quest service logic
  • Quest panel
  • Quest card UI
  • Quest display and state handling
  • Main-scene integration

8. Shops and item acquisition

The main game provides access to item purchasing and acquisition systems.

My contribution was primarily the game-ready panel and UI integration work, including:

  • Shop-related panel integration
  • Item display panels
  • Item detail interactions
  • Reusable item cells
  • Connections between item UI and inventory systems

9. Dungeon entry

Players enter the dungeon through the portal panel and can choose how to begin their run.

My contribution:

  • Dungeon-related UI panel preparation
  • Portal panel integration
  • Dungeon-entry UI
  • Save-point selection panel
  • Game-ready interface flow based on approved designs

The core dungeon and battle implementation was handled by another contributor.

10. Dungeon progression and rewards

The dungeon flow allows players to progress through stages, encounter enemies, and receive rewards. From the project integration, the flow includes:

  • Dungeon stage progression
  • Enemy encounter presentation
  • Battle UI
  • HP and currency display
  • Battle log presentation
  • EXP and item reward handling
  • Save-point/checkpoint support

I would describe my role here as UI preparation and integration rather than ownership of the complete combat system.
